# ERP UX correction coverage

16 November 2026. This maps the [60-rule research catalogue](2026-11-16-erp-ux-research.md) to the current implementation and representative regression checks. It describes code and test coverage, not measured operator productivity or a usability-study result.

**Implemented** means this increment changes the relevant behavior. **Retained** means the existing behavior remains appropriate and has a concrete source/test reference. **Applicability-limited** records a partial implementation, a feature that is not offered, or verification that cannot be inferred from these checks. A test link identifies the relevant check; its execution status and the final full-suite, isolated-site and native results belong in [UX_RUN_2026-11-16.md](../setup/UX_RUN_2026-11-16.md). No row claims Windows compilation, mobile-device usability, VoiceOver certification, translated locales/RTL, or hardware performance profiling.

## Follow-up verification on 18 November

The desktop toolbar now shares the overview's outer margins and maximum width. The company selector appears once in the workspace. Phone navigation stays within thumb reach in either orientation, and the workspace chooser marks the current destination. Rotating a phone with billing access brings the sales and stock summaries side by side. On knitting screens the drawer layout puts the operation in the top bar and keeps the company switch above the form. These choices follow Flutter's guidance on adapting navigation and controls to available space. [Flutter adaptive layouts](https://docs.flutter.dev/ui/adaptive-responsive/general)

The shared destination change removes the outgoing contents immediately and fades the incoming contents in place. Phone navigation uses the frosted treatment with an opaque accessibility fallback. Forms keep their solid reading surface. The root listens for changes to Apple's Reduce Motion flag as well as Android's Remove Animations preference. The knitting entry progress indicator reaches its final state after the server receipt. [Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials) · [Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion)

The pinned Flutter engine ran 41 passing cases across the navigation retention, industry home, mill navigation, knitting presentation, and workspace UI suites. The exercised sizes included 320- and 390-pixel portrait phones, 844 × 390 landscape, 834-pixel tablet and wide desktop. Four additional views were rendered from the real widgets with the bundled fonts and synthetic account data. Physical-device performance and assistive-technology walkthroughs remain open.

The continuity pilot uses the public invoice-template paper moving from its gallery to the larger sample preview. Knitting job selection currently changes the content of the same workspace pane, so adding a job route solely to animate it would introduce unnecessary navigation. The sample transition carries only public sample values, never live/customer financial data, has a site/account/company identity, and becomes static with reduced motion. Actual invoice register navigation retains its source context without adding a financial-content transition.
