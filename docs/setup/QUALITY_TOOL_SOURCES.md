These are changing security-data snapshots, not databases frozen to the executable release date. Grype's [installation defaults](https://raw.githubusercontent.com/anchore/grype/v0.121.3/grype/db/v6/installation/curator.go) retain checksum and age validation and consider data older than five days stale. The current database files expand to several GiB; their final sizes are recorded after preparation. Reserve space for downloads, unpacking, database indexes and replacement of an existing database; the helper conservatively requires **6 GiB free on both the image and its backing drive** before each normal database operation. This is a project headroom policy, not a publisher minimum. Grype database import also builds indexes, so the preparation remains a single active workload on this 8 GB Mac. The pinned [database adapter](https://raw.githubusercontent.com/anchore/grype/v0.121.3/grype/db/internal/gormadapter/open.go) and [import stages](https://raw.githubusercontent.com/anchore/grype/v0.121.3/grype/db/v6/installation/curator.go) show schema/index creation, SQLite analysis and a full database checksum before activation. The two Trivy download-only flags cannot be combined. This Java index is used for JAR identification and is unnecessary for the current Dart/Python source scope; it is excluded by default. The [Trivy database guide](https://trivy.dev/docs/latest/guide/configuration/db/) also states that the IaC checks bundle has no download-only CLI option. Preparing these vulnerability databases therefore does not establish complete offline readiness for IaC checks, Java archives or every later ecosystem lookup. No dummy scan is used to fetch those resources. ## Scope and installation readiness

The prepared runner uses one worker for Semgrep (`--jobs 1`), Trivy filesystem (`--parallel 1`), Checkov (`CHECKOV_WORKERS_NUMBER=1`) and Syft (`SYFT_PARALLELISM=1`).
